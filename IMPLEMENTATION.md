# Profile build notes

Every image in `assets/` and the README itself are generated by
`tools/build_assets.py`. Edit the source and rebuild; nothing generated is edited by hand.

```
pip install -r tools/requirements.txt     # fontTools + HarfBuzz, to outline the type
python tools/build_assets.py
```

## The system

This profile is the engineering half of [the portfolio](https://siddhartha-portfolio-nine.vercel.app).
The portfolio's hero says DESIGN BY SIDDHARTHA; this one says BUILT BY SIDDHARTHA. The
visual rules are taken from the portfolio repository (`styles/design-tokens.css` and its
components), not invented here.

| | Portfolio | Here |
|---|---|---|
| Ground | ink-950 `#0a0a0a`, dark-only | the same, so every image is dark in both GitHub themes |
| Text | paper-100 `#f5f5f5`, greys 200/300/400 | the same ramp |

| Shape | radius 0, hairline rules at 8% / 14% white | the same |

Small mono text is set in paper-300 rather than the portfolio's paper-400: at README
scale paper-400 on ink falls under 4.5:1.

## Type

GitHub serves README images with `default-src 'none'`, so a font can never load inside an
SVG. `tools/typeset.py` shapes each string with HarfBuzz (the font's own kerning) and draws
the glyphs as paths, so the pixels are the portfolio's typefaces and nothing is installed
to see them. The fonts are vendored in `tools/fonts/` (SIL OFL; licences alongside).
Because the text is outlines, each image's `alt` carries its full wording, and the README
builds `alt` from the same data it draws from.

## Layout

Canvas is 900 wide (GitHub's README column is about 888px, so 1 unit is about 1 css px),
40 margin, a 12-column grid with 20 gutters. Every image is full width and the README
stacks them as one poster.

Two details keep the stack seamless, and both matter:

- Each image is `<img ... align="top">` followed by `<br>`, all in one paragraph. That
  removes the paragraph margin and the baseline gap, so bands sit flush. If GitHub ever
  strips `align`, the page degrades to an 8px gap between bands, nothing breaks.
- No image may be shorter than one line of text (24px rendered). A shorter image leaves the
  remainder of its line box as a visible strip on narrow screens. This is why the
  Elsewhere register lives inside the Portfolio row instead of being its own image.

## Editing content

| What | Where in `tools/build_assets.py` |
|---|---|
| Palette, tracking | the token block at the top |
| Hero statement | `STATEMENT` (it is `content/profile.ts` in the portfolio) |
| Projects: name, context, summary, tools, link | `PROJECTS`; order is the order on the page; the first is the lead row |
| Portfolio, LinkedIn, Behance | `ELSEWHERE`, `PORTFOLIO`, `LINKEDIN`, `BEHANCE` |
| Section headings and intro | `work_header()` |
| Masthead verb | `closing()` and `hero()` |

Keep summaries to facts the repository shows, and state what does not exist yet beside what
does. Use ` ` to keep two words together (for example `In development`).
